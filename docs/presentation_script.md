전산세무 1급 이론 RAG 튜터. 숫자는 이 저장소에서 직접 돌려 얻은 값만 쓴다(2026-11-19 기준: `scripts/verify.py`, `scripts/eval_search.py`, `node scripts/check_ui.mjs`).

## 1. 문제 (1분)
> 전산세무 1급 이론은 30점입니다. 기출은 회차마다 PDF 로 흩어져 있고, "자기주식은 어떻게 처리하지?" 같은 질문을 하려면 회차를 하나씩 열어야 합니다. 일반 챗봇에 물으면 그럴듯하지만 **어느 회차 몇 번 문제가 근거인지** 알 수 없습니다.
> 그래서 질문하면 **실제 기출 문장만 모아서** 보여 주는 튜터를 만들었습니다. 답을 지어내지 않고, 모든 문장에 `128-6` 같은 출처가 붙습니다.

## 2. 범위 (1분)
- 하는 것: 이론 15문항(30점) 기출 540문항·36개 회차 검색, 주제 요약 카드, 기출 풀기(오답 잠금), 오답노트, 모의고사, 단원 분석·공부 순서, 용어 사전, 오프라인 목차.
- 안 하는 것: 실무(전산세무 프로그램) 시험, 대화형 Agent, 법령 원문 검색. API 키가 없어도 핵심 기능은 동작합니다(AI 설명만 키가 있을 때 덧붙음).

## 3. 데이터 흐름 (1분 30초) — `docs/architecture.md` 그림 1·2
> 원본은 확정답안 PDF·HWP 입니다. `sync_raw` 가 새 파일을 변환하고 정답표와 대조한 다음 SQLite 에 넣습니다. 이때 과목·세목·단원 태그가 붙고, 사람이 확인한 정정 목록(`corrections.json` 42건)이 적용됩니다.
> 질문 하나는 `search_theory`(일상어를 공식 용어로 넓힘 → 후보 → 희귀도 점수) → `build_summary`(문항 유형 판별 → 문장 쪼개기·합치기) → 화면 순서입니다. AI 는 **마지막 선택 단계**이고, 요약 카드의 문장만 근거로 쓰며 근거에 없는 출처는 경고합니다.

## 4. 시연 (3분 30초)
시연 전: `.venv/bin/python -m tutor.web` 로 서버를 켜고 브라우저에서 `http://127.0.0.1:8000` 을 연다. 오답노트·모의고사 기록이 비어 있으면 시연 ②를 먼저 한 번 해 둔다.

### 시연 질문 3개와 클릭 순서
**① 요약 카드 — "정상공손 비정상공손 처리"**
1. 상단 **질문** 탭 → 질문창에 입력 → **질문하기**.
2. 요약 카드에서 ✔ 맞는 문장 묶음과 ✘ 자주 나온 함정 묶음을 보여 준다. 형광펜 칠한 핵심어, 문장 끝의 `(70-10 · 핵심어 …)` 출처를 짚는다.
3. 맨 아래 **이 주제 기출 풀기** 를 눌러 기출로 이어지는 것을 보여 준다.

**② 오답 잠금 — 128회 1번**
1. **기출 답안** 탭 → 회차 `128`, 번호 `1` → **조회**.
2. 일부러 **틀린 보기**를 누른다 → "🔒 오답입니다."가 뜨고 보기가 모두 잠기며 **해설은 나오지 않는다**.
3. 다른 문항(128회 2번)에서 정답을 누르면 해설이 열린다.

**③ 오답노트 + 모의고사 OMR**
1. **오답노트** 탭 → 방금 틀린 128-1 이 보인다(다시 풀어 맞히면 빠진다).
2. **모의고사** 탭 → **모의고사 시작**. 오른쪽 **OMR 답안카드**(스크롤해도 고정)의 동그라미를 몇 개 누르면 왼쪽 문제지에도 같은 칸이 칠해진다. **제출하고 채점하기** → 점수·과목별 점수·틀린 문항 해설.
3. 폰 화면을 보여 줄 때는 창을 좁히면 OMR 이 하단 바로 바뀐다.

**④ 새 회차 자동 반영 (질문은 아님)**
1. 터미널에서 새 회차 폴더를 `data/raw/<회차>/` 에 복사(확정답안 파일).
2. `.venv/bin/python scripts/sync_raw.py` (또는 서버 재시작) → "N회 변환, 문항 수" 보고가 나온다. 정답표와 맞지 않으면 적재하지 않고 이유를 알려 준다.
3. 화면 **문제 분석** 탭의 회차 수가 늘어난 것을 확인.

## 5. 검증 — 실제 숫자만 (1분 30초)
- 단위 테스트 **231개 통과**(`scripts/verify.py`), 화면 자동 점검 **17개 시나리오 통과**(`node scripts/check_ui.mjs`, Chrome 으로 실제 클릭: 오답 잠금·모의고사·오프라인 파일·390px 가로 스크롤 없음·색 대비 4.5:1).
- 검색 정확도(정답 문항이 상위 3개 안에 들어오는 비율, hit@3):
  - 점검용 질문 15개: **14/15 (93%)**, 최신 10회분만 보면 15/15.
  - 따로 동결해 둔 30문항: **25/30 (83%)**. 이 30개는 검색을 고칠 때 맞춰 튜닝하지 않고 전·후 비교에만 씁니다(24/30 → 25/30).
- **솔직하게 말할 것 두 가지**
  1. 평가 질문과 정답은 **AI(Claude)가 DB 원문을 읽고 만들었습니다.** 사람이 쓴 1급 수험생 질문이 아니라서 점수가 **실제보다 높게 나왔을 수 있습니다.** 사람이 직접 질문을 쓰면 다시 재야 합니다.
  2. **Claude 가 실제로 만든 답변은 검증하지 못했습니다.** API 키가 없거나 인증이 실패해서, AI 설명 부분(출처 인용 일치)은 한 번도 실제 호출로 평가하지 않았습니다. 요약 카드와 검색 결과는 AI 없이 동작하는 부분이라 위 숫자가 해당합니다.

## 6. 한계와 다음 단계 (1분)
- 한계: 요약 카드의 문항 유형(옳은/옳지 않은)은 낱말 규칙으로 판별하므로 틀릴 수 있습니다(540문항 중 판별불가 1문항, 식별형 27문항은 문장 요약에서 제외). 일부 표가 있는 문항(HWP 원본 4개)은 원본과 대조하지 못했습니다. 중복 문항 12쌍 중 진짜 같은 문제는 3쌍입니다.
- 다음 단계: ① API 키를 넣고 Claude 답변과 인용 일치를 평가, ② 수험생이 직접 쓴 질문으로 hit@3 재측정, ③ 회차별 시험일과 세법 개정 메모 입력, ④ 의미 검색(벡터)은 사전·가중치 개선이 먼저이고 효과는 동결 30문항으로 전·후 비교.
